1 Functions

  1. Can you tell which of the arguments of myFunction are mandatory and which are optional?
myFunction <- function(x, y, verbose = FALSE){
  result <- x ** y
  if (verbose){
    print(result)
  }
  return(result)
}

x and y are mandatory, but verbose is optional because a default value has already been assigned in the function definition.

  1. What will be the output of the previous function if we type the following command myFunction(2, 3, TRUE)? Try to do it without running the code.

There will be two outputs of 8. One is printed, because verbose is set to TRUE. The other is the return value of the function, which is automatically printed if we do not assign the output of a function to a variable.

  1. Write any_na(), a function that takes two vectors of the same length and returns the number of positions that have an NA in, at least, one of the vectors.
# multiple options are available for ensuring the function takes arguments that are
# the same length. Extra points if they used a package like `assertthat`

# code below is what students might write to count all the NAs across both vectors
any_na <- function(x, y){
  stopifnot(length(x) == length(y))
  
  return(sum(c(is.na(x), is.na(y))))
}

# however, we want the number of positions, not number of total NAs
# again. There are many possible solutions. A simple one is to make a quick
# dataframe, as they have many functions available for NA operations
any_na <- function(x, y){
  # returns the number of positions that have an NA in at least one of the vectors
  stopifnot(length(x) == length(y))
  
  return(sum(!complete.cases(data.frame(x, y))))
}

If any intermediate variables were created, they should have sensible names. A comment explaining what the function does is also welcome! Because we know nothing about the problem application for this question, something like x and y can be reluctantly accepted as names for input variables.

  1. Write complementary(), a function that takes a DNA strand of variable length and returns its complementary strand.
# one option is using chartr, a function from base R built for character translation
complementary <- function(dna_seq){
  # returns complimentary strand for variable-length DNA strands
  return(chartr("ATGC","TACG", dna_seq))
}

# it wasn't specified what the strand would be in
# if we supplied the sequence as a vector, vectorised ifelse
# statement may be handy
complementary <- function(dna_seq){
  # returns complimentary strand for variable-length DNA strands
  return(dplyr::case_when(dna_seq == 'A' ~ 'T',
                          dna_seq == 'T' ~ 'A',
                          dna_seq == 'C' ~ 'G',
                          dna_seq == 'G' ~ 'C'))
}

Whatever was used, variable and argument names should be appropriate. X or y are no longer acceptable, as we know something about the problem for this question.

  1. Write a function that transcribes and translates a DNA strand into its corresponding protein sequence. You can assume that the length of the input DNA strand is a multiple of 3.
# students may have broken the problem into sub functions
# if this is the case, they should not be nested (they should
# not be defined within another function's body)
transcribe <- function(dna_seq){
  # converts from dna to rna
  rna_seq <- str_replace_all(dna_seq, 'T', 'U')
  
  return(rna_seq)
}

# even better than the option below would be putting the RNA codon table
# into a separate file which is loaded, so we can easily update it
translate <- function(rna_seq){
  # converts from RNA to protein
  # define an RNA codon table
  rna_codons = c("F", "L", "I", "V", "F", "L", "I", "V",

                "STOP", "R", "R", "G", "W", "R", "R", "G")
  names(rna_codons) <- c("UUU", "CUU", "AUU", "GUU", "UUC",
                         "CUC", "AUC", "GUC", "UUA", "CUA",
                         "AUA", "GUA", "UUG", "CUG", "AUG",
                         "GUG", "UCU", "CCU", "ACU", "GCU",
                         "UCC", "CCC", "ACC", "GCC", "UCA",
                         "CCA", "ACA", "GCA", "UCG", "CCG",
                         "ACG", "GCG", "UAU", "CAU", "AAU",
                         "GAU", "UAC", "CAC", "AAC", "GAC",
                         "UAA", "CAA", "AAA", "GAA", "UAG",

dna_to_protein <- function(dna_seq) {
  # convert from dna to protein
  rna_seq <- transcribe(dna_seq)
  protein_seq <- translate(rna_seq)
  return(protein_seq)
}

As before, variable names and function names should be appropriate. Comments are probably needed to make parts clear. It makes sense for separate operations to be broken into separate functions like above. This format is much-preferred.   1. Write clean_yes_no(), returning a logical vector.
clean_yes_no <- function(x) {
  v <- str_to_lower(str_trim(x))
  unrecognised <- setdiff(unique(v[!is.na(v)]), c("yes", "y", "no", "n"))
  if (length(unrecognised) > 0) {
    stop("Unrecognised value(s): ", paste(unrecognised, collapse = ", "), call. = FALSE)
  }
  case_when(v %in% c("yes", "y") ~ TRUE, v %in% c("no", "n") ~ FALSE, .default = NA)
}

Note what the function does not do: it does not guess. str_to_lower() and str_trim() handle the variation we expect — case and stray whitespace — and anything else is an error rather than a silent NA.

1.1 6a. Failing loudly

clean_yes_no(c("Yes", "No", "maybe"))
Error:
! Unrecognised value(s): maybe

Returning NA for unrecognised input would mean a new coding error — a "Y ", a "1", a "Unknown" — silently becomes missing data. The row count stays the same, nothing warns you, and your prevalence is quietly wrong. Erring forces somebody to look at it and decide.

1.2 6b. Prevalence

obese <- clean_yes_no(baseline$obesity)

c(n = length(obese), n_obese = sum(obese), prevalence = round(mean(obese), 3))
         n    n_obese prevalence 
  2400.000    810.000      0.338

33.8%, which matches the figure quoted in the dataset README — a useful check that the cleaning did what we intended rather than something plausible-looking.

1.3 6c. Reuse

t2d <- clean_yes_no(baseline$type2_diabetes)
round(mean(t2d), 3)
[1] 0.082

It works unchanged, and gives 8.2% — again matching the README. That is the argument for a function over a one-off fix: the same rule now applies to every yes/no column in the dataset, it is testable, and if the rule turns out to be wrong you change it in one place.

  1. check_range()
check_range <- function(x, min, max) {
  which(!is.na(x) & (x < min | x > max))
}

1.4 7a. imd_quintile

bad_imd <- check_range(baseline$imd_quintile, 1, 5)

baseline[bad_imd, c("participant_id", "imd_quintile")]
# A tibble: 1 × 2
  participant_id imd_quintile
  <chr>                 <dbl>
1 BIO00013                  9

One participant is coded 9, which is not a valid quintile. Most likely a missing-value code that was never translated on import — 9 and 99 are conventional “not known” codes in older clinical datasets.

1.5 7b. systolic_bp_mmHg

bad_bp <- check_range(baseline$systolic_bp_mmHg, 60, 250)

baseline[bad_bp, c("participant_id", "age_years", "systolic_bp_mmHg")]
# A tibble: 2 × 3
  participant_id age_years systolic_bp_mmHg
  <chr>              <dbl>            <dbl>
1 BIO00001              68             1330
2 BIO00002              74             1620

1330 and 1620 are 133.0 and 162.0 with a misplaced decimal point — both entirely plausible blood pressures, recorded ten times too large. Note that the range you choose is a judgement: too wide and you miss them, too narrow and you flag real outliers. State the range you used and why.
